# Internationalization (i18n)

curadiário speaks **pt-BR** during the pilot (es and en come back later, `docs/improvements.md`), using [`next-intl`](https://next-intl.dev) 4 with Next.js 16 (`cacheComponents` on).

## How the locale is picked

1. The `AD_LOCALE` cookie, set when the person switches language.
2. Without a cookie, the browser's `Accept-Language` header.
3. If nothing matches, `pt-BR`.

**URLs never carry the locale** (`localePrefix: 'never'`). An invite link, `/w/<slug>/invite#…`, is the same whoever opens it, and each person sees the UI in their own language. Under the hood, `src/proxy.ts` rewrites the request to `/<locale>/w/<slug>/invite`. The locale is then a *root param* (`next/root-params`), so pages stay static and cacheable: no page reads `headers()` or `cookies()`.

## Where things live

| Path | What it is |
| --- | --- |
| `src/i18n/locales.ts` | Locales, default locale, each language's name and suggested currency. **Single source.** |
| `src/i18n/routing.ts` | next-intl routing config (no prefix, `AD_LOCALE` cookie) |
| `src/i18n/request.ts` | Loads the current locale's messages and sets the default time zone |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `useRouter` and `redirect`. Use these, not the `next/*` ones. |
| `src/i18n/dates.ts` | `useFormatExchangeDate()` (wall-clock, no time-zone shift) and `useFormatMoney()` |
| `src/i18n/errors.ts` | Turns `cd_*` RPC error codes into translated messages |
| `src/proxy.ts` | Detects the locale and rewrites to `/<locale>/…` |
| `src/app/[locale]/` | Every page. The root layout lives here. |
| `src/types/next-intl.d.ts` | Typing: an unknown key or a missing argument fails the build |
| `messages/<locale>.json` | The copy. `pt-BR.json` is the source. |
| `scripts/check-messages.mjs` | `npm run i18n:check`: keys, ICU syntax and arguments |

## Rules for writing copy

- **Always ICU, never concatenation.** Write `"{count, plural, one {# pessoa} other {# pessoas}}"`, not `n + " pessoas"`. Word order changes between languages.
- **User content is never translated.** Workplace and client names, people's names, day notes and review notes appear as written.
- **Notebook dates and months** are wall-clock values. Use `useFormatDay()` / `useFormatMonth()` from `src/i18n/format.ts`, which format in UTC so they never shift a day. Real moments (notices, `sent_at`) use `useFormatClock()` / `useFormatMoment()` in the reader's time zone.
- **Money** uses the workplace's currency (`workplaces.currency`, BRL in the pilot), not the viewer's.
- **Neutral Latin American Spanish**, using "tú". "curadiário" is never translated and is always lowercase.
- **Words to avoid**: *diagnóstico*, *prontuário*, *paciente*, *tratamento*, except in the disclaimers that say curadiário is not care.
- **Naming** of namespaces and keys follows `docs/conventions.md`, section 8.

## What the workplace stores

The diary does not store a locale: every person sees the app in their own language.

## Adding a locale

1. Add the code to `locales` and `localeNames` in `src/i18n/locales.ts`.
2. Copy `messages/pt-BR.json` to `messages/<new>.json` and translate it.
3. Run `npm run i18n:check` and `npm run build`.

## Known limits

- **Server Actions and Route Handlers** have no root params. Pass the locale explicitly there: `getTranslations({locale, namespace})`.
